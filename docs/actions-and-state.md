# Самостоятельные действия и состояние игры

## Запуск проверочного фрагмента

На пустом экране редактора нажмите «Открыть проверочный фрагмент».
В открытом проекте та же команда доступна через «Сцена»; перед сменой проекта
редактор проверяет несохранённые изменения. Пример входит в редактор и не требует
скачивания ресурсов. Создаётся отдельная копия проекта с двумя простыми спрайтами
в системной временной папке `NovellMaker/Examples/<id>`. Для постоянной копии
используйте «Сохранить как…» — изображения переносятся обычным механизмом проекта.
Открытие примера не изменяет исходный проект.

1. F6 запускает фрагмент в MonoGame. Проводник говорит, молчащий путник движется
   восемь секунд. Движение продолжается, пока игрок читает текст.
2. В середине движения нажмите F7. Подождите и нажмите F8: положение и оставшееся
   время движения восстановятся. F7/F8 доступны также на предметах и выборе.
3. Enter открывает текст о терминале. Нажмите кнопку-предмет «Терминал» в центре сцены.
4. Lua создаёт два ответа на вопрос «2 + 2». Нажмите «4» либо «5». Перед ответом
   можно сохранить и загрузить игру. Второй вызов Lua получает ID нажатого предмета,
   возвращает `win` или `lose`, и сценарий выбирает соответствующую ветку.
5. Enter открывает обычный сюжетный выбор «Повторить / Завершить».
   Варианты выбираются мышью. Escape закрывает окно предпросмотра.

Это работающий пример ограниченной мини-игры из кнопок и сценарных действий.
Рисование произвольной графики, звуковое API, внешние Lua-файлы и игровой экспорт
в этот этап не входят.

## Авторская модель: фразы и вкладка «Скрипт»

Последовательность фраз — основной сценарий сцены. В «Репликах» автор пишет текст,
выбирает говорящего, состояние и размещение. Текст показывается автоматически,
затем движок ожидает продолжения игроком. Добавлять отдельные команды показа текста
и ожидания для каждой фразы не нужно.

Кнопка «Скрипт этой фразы» открывает вкладку «Скрипт» с выбранной фразой. В списке
реплик рядом с текстом видны количества блоков: «До», «Во время», «После».
Вкладка содержит карточки с описаниями, например «Во время фразы · Двигать —
Путник → X 83%, Y 100% за 8 с». Фразу можно выбрать в верхнем списке; там же доступны
«Начало сцены» и «Конец сцены».

Блоки имеют явное время запуска:

- **До фразы** — после применения обычных команд персонажей/размещения, перед текстом.
- **Во время фразы** — сразу после показа текста, до автоматического ожидания ввода.
  Движение запускается в фоне и продолжается, пока игрок читает.
- **После продолжения** — когда игрок завершил чтение этой фразы.
- **Начало / конец сцены** — общая логика до первой фразы или после последней.

«Добавить» создаёт выбранный тип блока для выбранной фразы и события; кнопка «Lua»
создаёт блок настоящего Lua-кода. Все блоки выбранной фразы видны вместе,
с указанием события. Стрелки переставляют блоки внутри одного события.
Разворачиваемая область «Изменить привязку» переносит блок к другой фразе/событию.
Изменения параметров вступают в силу кнопкой «Применить». Удаление подтверждается;
все операции поддерживают undo/redo. Параметры геометрии в GUI показываются в процентах.
Переход и выбор адресуют **фразу по её тексту**, без ручного выбора ID команды.

Фразы и блоки — одна модель: перестановка фразы переносит поведение вслед за ней.
Копирование фразы копирует её блоки с новыми ID; удаление фразы удаляет её блоки
и прямые переходы на неё одной операцией. Переименование сохраняет привязки.
Lua может пользоваться именованными ссылками `refs.traveller`, выбранными через GUI;
внутри они хранят стабильные ID. Строки с вручную написанными GUID автоматически
не переписываются. Внешние ссылки в коде нужно проверять после удаления объекта.

Встроенный пример использует эту модель: движение прикреплено к первой фразе,
терминал — ко второй, кнопки и два Lua-блока — к вопросу мини-игры, сюжетный выбор —
к продолжению каждой конечной ветки. Ввод на предмете не заменяет ввод чтения
автоматически: пример после щелчка явно переходит к следующей фразе.

Формат `.novell` — JSON v8. Коллекция `scriptBlocks` содержит `lineId`, `phase`
и `action`; `lineId` равен null только у начала/конца сцены. Компилятор строит обычные
действия общего исполнителя, включая стабильную точку входа каждой фразы.
Список фраз определяет порядок; порядок хранения блоков разных фраз его не меняет.
Прямой переход к фразе исполняет её размещение, команды персонажей и блоки «До».

v1–v7 открываются без неявной записи. Прежние сцены без скрипта сразу работают
как последовательность фраз. Произвольный поток действий v7 сохраняет прежнее
исполнение и показывается читаемыми карточками как импортированный сценарий;
автоматического преобразования произвольных циклов и Lua в привязки нет.
Смешивать этот поток с привязками запрещено. Новый встроенный пример и новые
сцены используют привязки; операция «Из реплик» больше не нужна.
Старые редакторы не читают v8. Неизвестные поля/типы, неверные привязки, повторные ID
и отсутствующие прямые ссылки проверяются при сохранении и чтении.

## Действия

| Действие | Поведение |
| --- | --- |
| Текст | Показывает локализованный текст по ID реплики, сохраняет время его начала. |
| Показать / Скрыть | Меняет видимость спрайтового объекта по ID персонажа. Скрытие сохраняет позу и размещение; движение может продолжаться скрыто. |
| Состояние | Меняет состояние любого персонажа, независимо от говорящего; скрытый объект не появляется. |
| Разместить | Устанавливает X/Y, масштаб и слой либо возвращает автоматику; отменяет предыдущее движение этого объекта. |
| Двигать | Запускает линейное изменение X/Y и масштаба; слой берётся из конечного размещения. Следующее действие начинается сразу. Новое движение того же объекта заменяет предыдущее с текущего положения. |
| Ожидать | `input` — Enter/Space/→ или «Вперёд»; `timer` — игровые секунды; `actions` — завершение всех текущих движений; `interaction` — щелчок по активному предмету. |
| Предмет | Регистрирует прямоугольную область и подпись; MonoGame показывает её кнопкой во время соответствующего ожидания. Пустой Token ожидания разрешает любой активный предмет. |
| Выбор | Останавливается на 1–8 вариантах со стабильными ID и целями scene/action. |
| Переменная | Записывает строку в состояние сюжета. |
| Условие | Если строковая переменная равна значению, переходит к цели; иначе исполняет следующее действие. |
| Перейти | Меняет сцену и следующую позицию по ID. |
| Lua | Ограниченный вызов формирует очередь этих же действий; API описан в [lua-api.md](lua-api.md). |

X/Y — доли сцены 1280×720 с якорем в нижнем центре спрайта, допустимый диапазон
−1…2. Масштаб — 0.05…5 относительно стандартного вписывания 360×560; слой — целое
−1000…1000. Параметры предмета — доли сцены с верхним левым якорем; прямоугольник
должен целиком находиться внутри сцены. Время — 0…86400 секунд, все числа конечные.
Несколько движений разных объектов работают параллельно. Для последовательности
добавьте ожидание `actions` или `timer`.

Щелчок принимается только во время ожидания `interaction`, по активной области,
с учётом масштаба окна и чёрных полей. Он записывает `input.object` и убирает набор
текущих предметов. Переход очищает предметы и оставшуюся очередь текущего Lua-вызова;
переменные, спрайты и движения сохраняются между сценами, пока сценарий их не изменит.
Цель перехода — самостоятельное действие. Для обычной сцены сначала создайте
действия кнопкой «Из реплик», чтобы выбрать цель в GUI.

## Исполнитель и время

`Core.Execution.ScenarioPlayer` владеет `GameState`; `ScenePlayer` остаётся фасадом
показа и навигации. Avalonia и MonoGame используют один исполнитель. Старого
отдельного исполнителя реплик больше нет. Модель проекта во время игры не меняется.

Состояние содержит сцену и следующее действие, текущий текст, строковые переменные,
видимость, состояния и размещения объектов, активные движения с исходными/конечными
значениями и прошедшим временем, ожидание, выбор, предметы и очередь Lua-команд.
Время изменяется только через `Tick(TimeSpan)`. При длинном кадре шаг делится на
границах таймеров и ожиданий движения. Ввод и выбор не продвигают игровое время.
`Cancel()` останавливает исполнение и активные действия с диагностикой.

На один проход допускаются 2048 действий без ожидания; на один Tick — 2048 границ
ожиданий. Это защита от сценарных циклов, а не планировщик произвольного параллельного
кода. Сейчас активные действия — только движения; звуковые и прочие ожидания
добавляются по мере реализации соответствующих систем.

В обычной сцене F6 по-прежнему восстанавливает команды до выбранной реплики;
«Назад» воспроизводит её предшествующие команды. В самостоятельном сценарии F6
запускает сцену с начала, «Назад» выключено: произвольный откат Lua и ветвлений
не реализован. Статический экран сцены редактора показывает начальное состояние
такого сценария; движение, взаимодействие и выбор проверяются по F6.

## Сохранение игры

Сохранение версии 1 содержит данные `GameState`, ID проекта и SHA-256 отпечаток
всего проекта с канонической сортировкой JSON-полей. Другой проект или изменённая
редакция отклоняются; перенос сохранений между редакциями ещё не реализован.
Проверка до замены состояния не даёт повреждённому файлу частично изменить игру.
Запись выполняется через соседний временный файл и замену целевого файла.

В MonoGame F7 записывает один быстрый слот, F8 загружает его:
`<LocalApplicationData>/NovellMaker/Saves/<project-id>.json`.
Сообщение об успехе или ошибке видно сверху. Перезапуск F6 с тем же проектом
позволяет загрузить этот слот. Создание новой копии примера создаёт новый ID проекта.

Поддержаны сохранения при чтении текста, движении, таймере, на выборе и во время
мини-игры из API. Сохраняются начальные параметры и остаток движения/ожидания,
текущее время анимации плашки и ещё не выполненные Lua-команды. Lua уже завершил
формирование очереди, поэтому загрузка её не запускает повторно.
Произвольный стек Lua не сериализуется. VM не живёт между вызовами.

Это не меню слотов, не автосохранение редактора и не общий rollback. Runtime
остаётся предпросмотром: упаковка самостоятельной игры и установщика ещё отсутствует.
