# Lua API v1

Используется MoonSharp 2.0.0, управляемая реализация Lua 5.2. Пакет закреплён в
lock-файлах; сборка и реальные вызовы проверены на .NET 10.0.204/Windows.
Нативное исполнение на Linux/macOS на этом этапе не проверено. Основания выбора:
отсутствие собственной нативной Lua-библиотеки, явный набор модулей и ограничение
инструкций через coroutine. Источники: [пакет](https://www.nuget.org/packages/MoonSharp/2.0.0),
[ограничение инструкций](https://www.moonsharp.org/coroutines.html),
[модули и ограничения](https://www.moonsharp.org/sandbox.html).

## Контракт вызова

Действие Lua содержит имя для диагностики и текст скрипта. Во вкладке «Скрипт»
выберите Lua, измените код и нажмите «Применить». Имя вида `terminal.lua`
служит источником ошибок с номером строки; это не путь к загружаемому файлу.
Внешние Lua-модули и редактор нескольких файлов ещё не реализованы.

Каждый вызов создаёт новую VM и **формирует очередь команд**. `game.wait(1)` добавляет
действие ожидания и сразу возвращается в Lua. После успешного завершения скрипта
движок последовательно исполняет очередь; в ожиданиях игровой цикл продолжает
обновлять движения и принимать ввод. Локальные переменные/функции Lua исчезают
после вызова. Для состояния между вызовами служит `game.set/get`.

Поэтому результат щелчка или завершившегося движения нужно читать **следующим
действием Lua**, после соответствующего ожидания. Код после `game.wait_click()`
в том же Lua-вызове вычисляется до щелчка. Этот контракт позволяет сохранять игру
без стека Lua. Добавленные после ожидания команды сохраняются обычными данными.

`game.get` видит записи `game.set`, выполненные ранее в этом же вызове.
Остальные чтения (`time`, `object`, `visible`) возвращают снимок состояния
на начало вызова; поставленные в очередь команды ещё не применены.

## Доступные функции

Все ID передаются строками GUID, значения переменных и результат мини-игры — строками.
X/Y и размеры предметов — доли сцены, время — игровые секунды.

| Функция | Значение |
| --- | --- |
| `game.get(name)` | Строка переменной либо `nil`. |
| `game.set(name, value)` | Запись строки; доступна последующим вызовам и условиям сценария. |
| `game.time()` | Игровое время на начало вызова. |
| `game.visible(id)` | Видимость спрайтового объекта, boolean. |
| `game.object(id)` | Новая таблица: `visible`, `state`; при ручном размещении также `x`, `y`, `scale`, `layer`. Отсутствующие данные — `nil`. Изменение таблицы не меняет движок. |
| `game.show(id)` / `game.hide(id)` | Показ/скрытие спрайтового объекта из библиотеки персонажей. |
| `game.state(id, stateId)` | Выбор состояния независимо от говорящего и видимости. |
| `game.place(id, x, y, scale, layer)` | Мгновенное размещение. |
| `game.auto(id)` | Возврат к автоматическому размещению. |
| `game.move(id, x, y, scale, layer, seconds)` | Фоновое линейное движение. |
| `game.text(lineId)` | Показ локализованного текста; без неявного ожидания и показа говорящего. |
| `game.wait(seconds)` | Ожидание таймера. |
| `game.wait_input()` | Ожидание Enter/Space/→ или кнопки «Вперёд». |
| `game.wait_actions()` | Ожидание всех активных движений. |
| `game.hotspot(id, label, x, y, width, height)` | Создание/замена кнопки-предмета с ID; верхний левый якорь. |
| `game.wait_click([id])` | Ожидание предмета; без аргумента принимает любой активный предмет. Щелчок записывает `input.object` и убирает текущие предметы. |
| `game.finish(result)` | Запись строки в `minigame.result`, которую читает условие сценария. |
| `game.jump(sceneId, actionId)` | Переход к действию. Остаток текущей очереди удаляется. |
| `game.jump_line(sceneId, lineId)` | Переход к фразе с применением её говорящего, размещения и блоков «До». |
| `game.choice(options)` | Ожидание выбора; массив 1–8 таблиц `{id=GUID, text=строка, scene=GUID, action=GUID}`. |

Геометрические диапазоны и поведение при переходах описаны в
[действиях и состоянии](actions-and-state.md). Неизвестные ресурсы, состояния,
неверные цели и параметры диагностируются движком. `game.finish` не закрывает
мини-игру автоматически: завершение определяется последующими действиями сценария.
Выбор результата и очистку объектов автор задаёт явно.

## Именованные ссылки и примеры

В Lua-блоке выберите объект из списка, задайте имя, например `traveller`, и нажмите
«Вставить именованную ссылку». В код вставляется `refs.traveller`. Кнопка «Применить»
сохраняет код и привязки вместе, с undo/redo. Значение ссылки — строка GUID, но
копировать или читать GUID автору не нужно. Привязка хранится в `ScriptAction.References`,
так что переименование персонажа не меняет код. Создаются ссылки также на состояния,
сцены, фразы и предметы. Имя ссылки состоит из латинских букв, цифр и подчёркиваний;
первый символ — буква или подчёркивание. Выбор того же имени заменяет его привязку.

В блоке «Во время фразы»:

```lua
-- Подключите ссылки traveller и guide через редактор.
-- Текст текущей фразы и ожидание продолжения добавляет сам движок.
game.move(refs.traveller, 0.8, 1, 1, 0, 3)
game.move(refs.guide, 0.2, 1, 1, 1, 2)
```

В блоке «После продолжения» можно дождаться движений и перейти к фразе:

```lua
game.wait_actions()
game.jump_line(refs.next_scene, refs.next_phrase)
```

`game.jump_line(sceneId, lineId)` адресует начало фразы, включая размещение,
говорящего и её блоки «До». `game.jump(sceneId, actionId)` остаётся низкоуровневым
API для существующих сценариев. Для обычного авторского сценария используйте
`jump_line` и именованные ссылки.

Мини-игра встроенного примера создаёт две кнопки обычными блоками у фразы-вопроса.
Первый Lua-блок той же фразы:

```lua
game.wait_click()
```

Следующий Lua-блок после завершения ожидания читает ответ. Подключите `correct`
к предмету «4»:

```lua
if game.get("input.object") == refs.correct then
    game.finish("win")
else
    game.finish("lose")
end
```

Затем обычные блоки условия и перехода выбирают фразу успеха/неудачи.
Полностью запускаемый пример доступен через «Сцена → Открыть проверочный фрагмент».
Lua-блоки и визуальные блоки компилируются в действия одного исполнителя;
это не две независимые копии сценария. Общего редактируемого Lua-файла,
автоматически обратимо преобразуемого в блоки всей сцены, пока нет.

## Ограничения и ошибки

- Загружается `CoreModules.None`: нет `io`, `os`, `require`, `load`, `dofile`,
  CLR, процессов, сети, файлов, `print`, стандартных библиотек `math/string/table`
  и пользовательских coroutine. Язык поддерживает обычные выражения, условия,
  циклы, функции и литералы таблиц. Подключение библиотек — отдельное расширение API.
- Один вызов: не более 32768 UTF-16 символов исходника, 20000 инструкций MoonSharp
  и 256 выдаваемых команд. Достигший бюджета вызов завершается ошибкой; его ещё
  не принятая очередь целиком отбрасывается. Порог инструкций не является лимитом
  памяти и не даёт изоляцию отдельного процесса. Огромные строки/таблицы могут
  потреблять память; запуск недоверенных проектов не заявлен безопасной песочницей.
- VM работает только во время ограниченного формирования очереди, без ожиданий
  внутри произвольного Lua-стека. Межкадровые Lua-update/draw callbacks, произвольная
  графика, звук, вращение, случайные числа и внешние побочные эффекты не предоставлены.
- Ошибка останавливает дальнейшее исполнение сценария и показывается в диагностике
  игрового окна. Текст Lua-ошибки содержит имя скрипта, ID действия и строку.
  Уже исполненные до ошибки сценарные команды не откатываются автоматически.
  Полный rollback и миграции сохранений между изменёнными проектами отсутствуют.
- Сохранение поддерживается между вызовами, включая ожидания с оставшимися
  командами очереди. Возобновление произвольного Lua-стека не поддерживается.
