# Lua-ресурсы и модули

[Оглавление](index.md) · [Модель исполнения](execution-model.md) · [События](events.md) · [Квоты](limits.md)

Ресурс создаётся через обозреватель проекта и редактируется внешним приложением. Снимок кода — в `.novell`; рабочий UTF-8 файл `Scripts/<ID без дефисов>.lua` имеет приоритет при чтении. Имя ресурса не меняет ID, путь или привязки. F5 перечитывает вручную; watcher с debounce обновляет диагностику. F6/Save As/экспорт дополнительно захватывают текущие файлы. Ошибки блокируют запуск/экспорт. Save As не должен молча перезаписывать отличный исходник.

Один и тот же Lua-ресурс может использоваться как сценарный вызов **game.run** или как **ui.import**, но окружения различны. Для общего сценарного кода нет импорта/require: запускайте ресурс очередью. Модуль ui возвращает таблицу экспортов; имена её авторских функций не входят в API движка. Вложенные ссылки на другие Lua-ресурсы объявляйте в свойствах **того файла**, который делает импорт.

Модуль имеет отдельные таблицы globals/ui/math/string/table и собственный `modules`; `refs` в модуле — пустая таблица, `audio` вообще не устанавливается. Передавайте handles и WAV ID из корня параметрами авторских функций. Предоставленные API-callbacks привязаны к одному экземпляру и его состоянию, поэтому модуль может вызвать ui.set_text с переданным собственным handle. Глобал/замыкание модуля живёт в VM и кешируется по ID до закрытия экземпляра; не сериализуется.

Общие правила: [модель исполнения](execution-model.md), [квоты графа](limits.md#modules), [проверки модулей](../../tests/NovellMaker.Core.Tests/Screens/LuaModuleTests.cs). Граф заранее проверяется весь, даже если ветка с импортом не выполнится: корень+модули <=32 ресурсов, глубина <=16, сумма кода <=65536, ссылок <=256, импортов одного файла <=32. Каждый файл проходит общий preflight 32768/4096/64/128/256. Общий бюджет загрузки/обработчика делят все файлы.

В приведённом примере создайте ресурс helper с `return {caption=function() return "Готово" end}`, объявите ссылку `helper` на него в корневом ресурсе, назначьте корневой ресурс обработчиком холста и refs.label компоненту Text.

<a id="ui-import"></a>
## ui.import

Импортировать объявленный Lua-модуль и получить его экспорты.

```lua
ui.import(resourceId) -> table
```

**Доступность:** ui при загрузке исходника, on_load/on_event, модуль, мини-игра; restore допускает импорт, но не запрещённые эффекты импортируемого кода.

**Аргументы и ошибки:** resourceId: строка GUID из modules.<alias> текущего файла. Путь/необъявленный ID/число/nil запрещены. Используйте точное значение из modules: кеш публикации парсит его как GUID.

**Возврат:** Таблица экспортов модуля. Один объект таблицы возвращается при повторном импорте в том же экземпляре.

**Эффект и ограничения:** Модуль вычисляется при первом импорте в текущей coroutine и общем бюджете вызова, в отдельном окружении. При импорте на верхнем уровне команды запрещены; из обработчика функции модуля используют возможности текущего обработчика. Циклы/неполный граф/возврат не таблицы — ошибка. Общие [квоты](limits.md), [атомарность](execution-model.md#batch) и [lifecycle/сохранение](execution-model.md#lifetime) применяются, если здесь не указано исключение.

**Пример** (предусловия refs/ресурсов приведены в начале страницы; это фрагмент соответствующего обработчика, если не показан полный return):

```lua
local helper = ui.import(modules.helper)
return {on_load=function() ui.set_text(refs.label, helper.caption()) end, on_event=function(e) end}
```
