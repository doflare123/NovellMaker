# Импорт персонажей и диалога

[Руководство](engine-guide.md) · [Оглавление](index.md) · [Проверка](compatibility.md)

Откройте проект и выберите **«Проект → Импорт персонажей и диалога…»**. Во вкладке «Реплики» доступна та же команда «Импорт…». Поддерживаются JSON, CSV и TSV до 32 МиБ. Импорт доступен без правки исходников движка. Он загружает авторские данные, не исполняет Lua и не создаёт произвольные потоки сценарных команд.

## Мастер

1. Выберите файл. **Источник** — постоянное имя набора, по умолчанию имя файла без расширения. При повторном импорте сохраните это имя, даже если переименовали сам файл. Разные наборы должны иметь разные имена источника.
2. Проверьте папку ресурсов и язык по умолчанию. Пути из файла считаются относительно этой папки, по умолчанию папки самого файла. Для реплик без ключа сцены выберите текущую или новую сцену. В существующую сцену новые реплики вставляются после выбранной; если выбранной нет, в конец.
3. Для CSV/TSV выберите разделитель и назначьте колонки. «Не использовать» отключает поле. Для импорта только персонажей отключите колонку текста. Текст без персонажа становится рассказчиком. Можно загрузить сохранённый профиль или отметить «Сохранить профиль» и указать имя нового.
4. Нажмите «Разобрать и сопоставить персонажей». Для каждого внешнего персонажа выберите существующего, «Создать» либо рассказчика. Выбор действует сразу на все его реплики. Совпадение имени с единственным персонажем предлагается автоматически; одинаковые имена требуют явного выбора. При повторном импорте приоритет имеют сохранённые внешние ключи.
5. Проверьте «Предпросмотр»: новые персонажи/сцены, новые и обновляемые реплики, позы, назначения/замены WAV, ошибки ресурсов. При ошибках пакет не применяется. Можно отключить «Импортировать WAV» или «Импортировать изображения» и построить предпросмотр заново, чтобы загрузить только текст и персонажей.
6. «Применить импорт» копирует ресурсы и меняет проект **одной операцией Undo/redo**. Отмена мастера ничего не копирует и не сохраняет профиль. При ошибке копирования или изменении проверенных байтов ресурса весь пакет отклоняется, его незавершённые копии удаляются. Успешный Undo оставляет файлы для redo, как при обычном импорте ресурсов.

Профиль содержит разделитель, язык и соответствие имён колонок полям. Профили и соответствия внешних ключей входят в проект: сохраняются при Save As, восстановлении и undo/redo. Изменение настроек мастера отменяет прежний предпросмотр; перед применением его нужно повторить.

## CSV/TSV

Первая строка — непустые уникальные заголовки. Названия и порядок произвольные: сопоставьте их в мастере. Разделители — запятая, точка с запятой или табуляция. UTF-8/BOM поддерживается; запятые, разделители и переводы строк внутри поля заключаются в двойные кавычки, кавычка экранируется удвоением. Один файл — до 20000 строк данных. Повтор заголовков и разное количество полей отклоняются.

| Поле мастера | Значение |
| --- | --- |
| Текст | Текст реплики; при отключении импортируются только персонажи |
| Персонаж | Имя говорящего; пустое поле — рассказчик |
| Ключ персонажа | Стабильный внешний ключ; если отсутствует, используется имя |
| Ключ реплики | Необязательный стабильный ключ для повторного импорта |
| Язык | Код языка; пустое поле наследует язык мастера |
| WAV | Необязательный относительный путь записи |
| Изображение | Необязательный относительный путь PNG/JPEG позы персонажа |
| Поза | Ключ и имя статической позы; при изображении без позы используется `default` |
| Сцена | Название отдельной импортируемой сцены |
| Ключ сцены | Её внешний ключ; если нет, используется название сцены |

Минимальный пример: [dialogue.csv](../../examples/dialogue-import/dialogue.csv). Он создаёт персонажей и реплики без графики и озвучки. Можно переназначить имена на персонажей текущего проекта.

```csv
Код;Ключ персонажа;Имя;Реплика;Язык;Запись
line-001;lena;Лена;Ты тоже это слышал?;ru;voice/lena_001.wav
line-002;anton;Антон;Слышал. Подожди здесь.;ru;
line-001;lena;Лена;Did you hear that too?;en;
```

Несколько строк с одним ключом реплики и разными языками объединяются в одну реплику. Повтор ключа и языка либо разные говорящие/позы у одного ключа отклоняются. Повторяющиеся сведения о персонаже должны иметь одинаковое имя, а один ключ его позы — одинаковое изображение. Колонки WAV и изображения можно полностью исключить. Пустая ячейка WAV сохраняет уже назначенный голос при обновлении, а не удаляет его.

## JSON v1

Это отдельный формат обмена с `version: 1`, не JSON проекта `.novell`. Неизвестные и повторные поля, неподдерживаемая версия и некорректные типы отклоняются. Пример без ресурсов: [dialogue.json](../../examples/dialogue-import/dialogue.json).

```json
{
  "version": 1,
  "language": "ru",
  "characters": [
    {
      "key": "lena",
      "name": "Лена",
      "defaultPose": "idle",
      "poses": [
        { "key": "idle", "name": "Обычная", "image": "characters/lena.png" }
      ]
    }
  ],
  "scenes": [
    {
      "key": "arrival",
      "name": "Прибытие",
      "lines": [
        {
          "key": "arrival-001",
          "speaker": "lena",
          "pose": "idle",
          "texts": { "ru": "Ты тоже это слышал?", "en": "Did you hear that too?" },
          "voices": { "ru": "voice/lena_001.wav" }
        },
        { "key": "arrival-002", "text": "За дверью щёлкнул замок.", "unvoiced": ["ru"] }
      ]
    }
  ]
}
```

- `characters` необязателен. `key` и `name` обязательны у заданного персонажа; `poses` содержит статические позы с обязательными `key`, `name`, `image`. `defaultPose` выбирает ключ исходной позы; иначе используется первая новая поза, если у персонажа исходной ещё нет. Персонаж без поз создаётся как заготовка без графики; для полноценного показа настройте позы в библиотеке.
- `scenes` необязателен. У сцены `key` задаёт постоянное соответствие, `name` — название, `lines` — реплики. Верхнеуровневый массив `lines` направляется в выбранную в мастере сцену. Можно передать только персонажей. При наличии обоих массивов они обрабатываются последовательно.
- У реплики `speaker` ссылается на ключ персонажа. Необъявленный ключ предлагается как новый персонаж с этим же именем. Пустой/отсутствующий `speaker` — рассказчик. `pose` — ключ импортируемой позы либо имя существующей позы сопоставленного персонажа.
- `texts` и `voices` — словари по языкам. Для одной локали можно использовать сокращённые `text`, `voice`, `language`; язык наследуется от реплики, затем файла, затем мастера. Нельзя дважды задать один язык через сокращённую и полную форму. Для каждой реплики нужен хотя бы один текст.
- `unvoiced` — языки, на которых автор намеренно оставляет реплику без голоса. При включённом импорте WAV эта отметка снимает прежнюю запись данного языка. Нужен текст этого языка в той же импортируемой реплике; одновременное задание WAV запрещено. При выключенном импорте WAV озвучка и эти отметки не меняются.

## Повторный импорт и ресурсы

Сопоставление идёт по **имени источника, типу объекта и внешнему ключу**. Внутренние GUID и ключи переводов создаёт редактор. Номер строки, её текст и порядок не используются для поиска существующей фразы. Ключи реплик должны быть уникальными во всём наборе, включая разные сцены. Сохранённое сопоставление персонажа с рассказчиком тоже восстанавливается.

При включённом «Обновлять по внешним ключам» меняются только переданные переводы, говорящий, явно выбранная поза и переданная озвучка. Прочие языки, ID, порядок и ScriptBlocks сохраняются; отсутствующие в файле объекты не удаляются. Имя ранее связанного персонажа и название связанной сцены обновляются. Переименование существующего персонажа, выбранного впервые вручную по другому имени, не навязывается. Для поз по возможности сохраняется ID. Пакет не перемещает связанную реплику между сценами автоматически: при несовпадении сцены выдаёт ошибку.

Без ключа реплика всегда добавляется заново. Снятие «Обновлять по внешним ключам» явно добавляет новые реплики/сцены и переназначает их ключи на новые ID; последующие обновления относятся к ним. Персонажи по-прежнему определяются явным сопоставлением мастера. Отсутствие ключей персонажа/сцены в CSV заменяется именем, поэтому для безопасных переименований используйте отдельные колонки ключей.

Ресурсные пути должны быть относительными путями внутри выбранной папки. Поддерживаются вложенные папки; абсолютные пути, `..` и символические ссылки внутри набора отклоняются. WAV проверяются общим импортёром: PCM 16 bit, mono/stereo, 8000–48000 Гц, до 2 ГиБ. PNG/JPEG проверяются общим декодером, с его пределами 64 МиБ сжатых данных, 8192 по стороне и 32 млн пикселей. Один файл, используемый несколькими позами/фразами, копируется один раз; повторный импорт неизменившихся байтов переиспользует зарегистрированный ресурс. Изменённый ресурс добавляется отдельно, не перезаписывая прежние файлы, необходимые для Undo или других ссылок.

Импорт не переносит слоистую/покадровую анимацию, Lua, мини-игры, выборы, переходы и фоновые музыкальные настройки. Статическое изображение не заменяет существующую слоистую/покадровую позу. Произвольный импортированный сценарный поток не смешивается автоматически с привязками реплик. Эти ограничения относятся к этому формату обмена, а не к возможностям самого редактора.

Проект **v25** хранит сведения в `imports.bindings` и `imports.profiles`; проекты v24 и ниже получают пустые данные при миграции. Сохранения игрока и Lua API не менялись; точная ревизия содержимого проекта, как прежде, влияет на совместимость игровых слотов. Для экспорта нужен подготовленный runtime-шаблон v25.
