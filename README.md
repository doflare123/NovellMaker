# NovellMaker

Кросс-платформенный движок и визуальный редактор независимых визуальных новелл.
Реализованы управление проектом, текстовый редактор сцен с оформлением диалоговой
плашки, импорт PNG/JPEG, задник, персонажи со сменными состояниями и игровой
предпросмотр в отдельном окне MonoGame. Исполняется линейная сцена с показом,
сменой состояния, скрытием и ручным размещением персонажей, масштабом и порядком
спрайтов. Добавлены самостоятельные действия, время и ожидания, переменные,
выборы, переходы, небольшое Lua API и быстрое сохранение/загрузка состояния игры.
Добавлены экспорт автономной папки Windows x64 и установщик EXE через GUI.
Звук: общий AudioService, потоковый PCM WAV, группы Master/sound/effect/voice, фон сцены, эффекты и озвучка фраз по языкам. Во вкладке «Звук» — импорт и привязки; в игре F9 — микшер, P — меню паузы. Штатные меню используют общий стек экранов, Tab/Shift+Tab и Enter/Space; Esc возвращает на предыдущий экран. [Звук](docs/audio.md), [экраны и ограничения](docs/game-screens.md).

[Проверка звука: 393 пройдено, 0 ошибок, 3 пропущено](docs/verification-audio-2026-10-19.md).

## Проверочный фрагмент и действия

Нажмите «Открыть проверочный фрагмент» на пустом экране или в меню «Сцена», затем
F6. Молчащий персонаж движется во время чужой реплики; щелчок по терминалу запускает
Lua-мини-игру, её результат выбирает ветку. F7 сохраняет игру, F8 восстанавливает
её, включая незавершённое движение и ожидание ответа. Каждое открытие примера
создаёт отдельный проект во временной папке; «Сохранить как…» делает постоянную копию.

Фразы задают порядок сцены, говорящего и размещение. Кнопка «Свойства и события»
показывает боковую панель свойств и событий, сохраняя открытый текст. Блоки привязаны к «До фразы», «Во время фразы»,
«После продолжения». Текст и ожидание чтения добавляются автоматически.
Карточки показывают персонажей, параметры и цели переходов по текстам фраз.
Можно добавить блок настоящего Lua-кода; ссылки вставляются по имени, например
`refs.traveller`. При перестановке и копировании фразы блоки следуют за ней.
Редактирование, привязки и удаление поддерживают undo/redo.

«Ресурсы → Lua-скрипты»: самостоятельные ресурсы кода с устойчивыми ID и выбором
внешнего редактора по умолчанию. Настоящие UTF-8 `.lua` лежат в `Scripts/<ID>.lua`;
после сохранения файла код автоматически обновляется и проверяется без исполнения.
Встроенного поля Lua-кода нет. Скрипт можно запустить в начале
сцены, у фразы или через `game.run(refs.script)` из другого скрипта. Код хранится
в снимке проекта; F6, Save As и экспорт читают актуальные файлы. Ошибки блокируют
запуск и экспорт. [Инструкция и ограничения](docs/script-resources.md).
[Проверка изоляции Lua и инспектора: 426 пройдено, 0 ошибок, 3 пропущено](docs/verification-lua-isolation-2026-10-19.md).

MoonSharp проверяет синтаксис и исполняет код в отдельном ограниченном процессе.
Вложенность из аудита отклоняется до парсера; OOM/авария worker возвращают диагностику
без потери процесса редактора. На Windows ограничены куча CLR (64 МиБ), память процесса
(256 МиБ) и время вызова (5 секунд). [Точные бюджеты](docs/lua-api.md#ограничения-и-ошибки).
Скрипты создаются и открываются через контекстное меню обозревателя, параметры —
в панели «Свойства»; отдельный документ библиотеки больше не открывается.

Прежние потоки v7 сохраняют своё исполнение; новые сцены и встроенный пример
используют привязки к фразам. Сценарий с блоками запускается по F6 с начала,
произвольный откат назад пока выключен. Сохранения требуют точной редакции проекта.

[Действия, состояние и проверка примера](docs/actions-and-state.md) ·
[Lua API v1, примеры и ограничения](docs/lua-api.md).

Событийный Lua экранов работает отдельным долгоживущим worker: VM на экземпляр,
ограниченные on_load/on_event и атомарные изменения своего экрана. Подключён к штатной
паузе; Esc/P и штатное закрытие доступны при сбое обработчика. Авторский GUI экранов
остаётся следующим этапом. [Контракт и бюджеты](docs/screen-lua.md).

## Экспорт Windows x64

«Сборка → Экспорт игры для Windows x64…» собирает текущий снимок проекта в новую
папку. Выберите стартовую сцену и место для сборки. Передавайте всю папку;
запуск — `NovellMaker.Runtime.exe`, редактор, SDK и отдельная установка .NET не нужны.
Готовые папки не перезаписываются. Быстрый слот игры находится в профиле игрока,
отдельно от слота предпросмотра.

Разработчик поставки один раз выполняет `./scripts/prepare-windows-export.ps1`,
чтобы включить автономный шаблон в редактор. Экспорт каждой новеллы не вызывает SDK.
«Сборка → Установщик игры EXE…» создаёт один передаваемый EXE с версией,
необязательной ICO, установкой для текущего пользователя, ярлыками и удалением.
Для поставки с компилятором используйте `./scripts/prepare-windows-installer.ps1`.
Сохранения не удаляются вместе с игрой. [Установщик и проверка](docs/windows-installer.md).
[Проверка EXE: 383 пройдено, 0 ошибок, 2 пропущено](docs/verification-installer-2026-10-19.md).
Подпись EXE и изменение иконки самого игрового runtime пока не реализованы.
[Подготовка, управление, сохранения и диагностика](docs/windows-export.md).
[Проверка исполнения и экспорта: 374 пройдено, 0 ошибок, 2 пропущено](docs/verification-export-2026-10-18.md).

## Запуск

Нужен .NET SDK 10.0.204; допускаются более новые патчи этой SDK feature band.
Зависимости Avalonia 12.1.0 и MSTest закреплены в проектах и packages.lock.json.
Git нужен только для отображения состояния репозитория и интеграционных Git-тестов.

```powershell
$env:AVALONIA_TELEMETRY_OPTOUT = '1'
dotnet restore NovellMaker.slnx --locked-mode
dotnet run --project src/NovellMaker.Editor
```

В bash первый шаг: `export AVALONIA_TELEMETRY_OPTOUT=1`.
Это штатное [отключение телеметрии сборки Avalonia](https://github.com/AvaloniaUI/Avalonia.BuildServices#opting-out).
Оно также позволяет собирать проект в окружениях с ограничением записи в профиль.
При первом восстановлении зависимостей требуется доступ к NuGet либо заполненный кэш пакетов.

## Рабочее пространство

- За заголовок панель перетаскивается к нужному краю другой панели. Подсветка
  показывает область закрепления; Escape отменяет перенос. Разделители меняют размеры.
- Кнопка `×` скрывает панель. Вернуть её можно через «Вид → Панели».
  Меню `…` в заголовке позволяет выбрать панель и сторону закрепления с клавиатуры.
- «Вид → Восстановить расположение панелей» возвращает исходную компоновку.
  Настройки хранятся в локальном профиле ОС: `NovellMaker/workspace.json`.
- Экран сцены отделён от редактора реплик и показывает текущую открытую сцену.
  Нативный запуск MonoGame по F6 остаётся отдельным игровым окном.
- «Параметры проекта → Вид обозревателя проекта» переключает логическую иерархию
  новеллы и папки проекта: «Сцены», «Персонажи» плюс настоящие папки/файлы рядом
  с `.novell`. Слева показана навигация по папкам, справа — плитки текущей папки,
  для изображений — миниатюры. Двойной щелчок входит в папку; сценарий открывается
  двойным щелчком или Enter. Сверху доступны путь, назад/вперёд, уровень выше и поиск.
  Сцены и персонажи доступны до первого сохранения; для файлов на диске проект
  нужно сохранить. Папки раскрываются по мере просмотра; `.git` скрыт, ссылки на
  каталоги не обходятся. Зарегистрированное изображение открывает библиотеку,
  текущий `.novell` — параметры проекта. Остальные файлы показываются без редактора
  их содержимого. F5 обновляет файлы и Git-статусы; отдельный список изменений
  Git доступен в иерархическом режиме; плитки показывают статусы файлов,
  общий счётчик Git учитывает правила `.gitignore`.

Удаление: выделите объект в дереве или плитках и нажмите Del. Сцены, персонажи,
состояния, изображения, файлы и папки удаляются после подтверждения. Те же диалоги
используют кнопки удаления сцен, реплик, персонажей, состояний, изображений и команд
размещения. В текстовых полях Del продолжает удалять текст. Ctrl+Z восстанавливает
объекты, файлы и их привязки в текущем сеансе; Ctrl+Y повторяет удаление.
Сведения о резервных копиях и ограничениях — [docs/deletion.md](docs/deletion.md).

## Что работает

- Создание независимых проектов, открытие, сохранение, «Сохранить как» и закрытие.
- Нейтральная тёмная тема, меню, панель команд, вкладки параметров и сцен, обозреватель,
  сведения о проекте и журнал сообщений. Все пять панелей, включая экран сцены,
  можно скрывать, менять в размере и закреплять у края другой панели.
  Расположение и размеры сохраняются локально между запусками редактора.
- Режимы обозревателя «Иерархия новеллы» и «Папки и файлы» в параметрах проекта;
  выбор сохраняется в `.novell` и поддерживает undo/redo.
- Редактирование названия без изменения постоянного ID. Несохранённые изменения
  отмечены `*`; пустое название запрещает сохранение.
- Подтверждение сохранения, отказа или отмены при закрытии окна/проекта и замене
  проекта. Ошибка записи или отмена диалога сохранения оставляет черновик открытым.
- Отказ от перезаписи открытого проекта, если его данные изменены, удалены или
  повреждены вне редактора. Можно сохранить свою версию другим именем.
- JSON v10 в файле `.novell`: сведения о проекте, сцены, блоки и ресурсы Lua, реплики с текстами по языкам,
  настройки диалоговой плашки, изображения, задники, персонажи, состояния и команды реплик.
  Проекты v1/v2/v3/v4/v5/v6/v7/v8/v9 мигрируют в памяти при открытии;
  исходный файл меняется только при явном сохранении. Неизвестные поля,
  повторяющиеся свойства, повреждённые данные и неподдерживаемые версии отклоняются.
- Запись через уникальный временный файл в том же каталоге и замену целевого файла;
  при ошибке временный файл удаляется.
- Git-статус файлов в обозревателе: индекс и рабочая копия, новые файлы, удаления,
  переименования и конфликты. Git учитывает `.gitignore`, вложенные правила и отрицания.
  Если проект лежит внутри общего репозитория, учитывается только каталог проекта.
- Git проверяется после открытия/сохранения, при возвращении в окно и по F5.
  Отсутствие Git, отсутствие репозитория и ошибки проверки показаны отдельно.
- Создание, переименование и удаление сцен; несколько открытых вкладок. Закрытие
  вкладки сохраняет её изменения в проекте, не удаляя саму сцену.
- Добавление, редактирование, дублирование, удаление и перестановка реплик.
  ID и ключи текста сохраняются при изменении порядка; копии получают новые ключи.
- Тексты каждой реплики хранятся по языкам. Поле языка в сцене переключает
  редактируемый перевод, не перезаписывая другие языки.
- Undo/redo изменений названия проекта, сцен, реплик, оформления, импорта,
  названий изображений и выбора задника. Последовательный
  ввод в одно поле объединяется в операцию; история ограничена 200 операциями.
- «Назад» и «Вперёд» выбирают ровно соседнюю реплику в редакторе и недоступны
  на границах сцены. Это навигация автора, а не игровой rollback.
- Общий CSS плашки и переопределение для сцены, образец оформления, запуск и
  остановка анимации. Поддерживаемое подмножество описано в [CSS-справке](docs/dialogue-styles.md).
- Настройки видимости индикатора озвучки, паузы/продолжения и навигации сохраняются
  в проекте. Образец показывает отсутствие озвучки и недоступные аудиокнопки:
  реальная проверка звука доступна в F6; аппаратный прогресс пока не отображается.
- Библиотека изображений с поиском, миниатюрами и предпросмотром. Импорт копирует
  PNG/JPEG в `Assets/Images/` внутри проекта; исходный файл после этого не нужен.
  Название ресурса можно менять без изменения ID и привязок сцены.
- Вкладка «Задник» в сцене: выбор изображения, статический предпросмотр,
  диагностика отсутствующего файла или неизвестного ID. F5 обновляет ресурсы и Git.
  При сохранении в другую папку копируются все зарегистрированные изображения;
  конфликтующий файл с другим содержимым не перезаписывается.
  Порядок работы и ограничения описаны в [справке по изображениям](docs/images.md).
- Библиотека персонажей: имя, состояния со стабильными ID и собственными спрайтами,
  выбор исходного состояния. Реплика может назначить говорящего и состояние,
  например `sad`, а также скрыть одного персонажа перед показом реплики.
  Говорящий появляется автоматически; остальные остаются до явного скрытия.
  Переименование персонажа и состояния сохраняет связи. Копия реплики сохраняет
  команды, получая новые ID и ключ текста. Эти изменения поддерживают undo/redo.
- Вкладка «Размещение»: выбор реплики и персонажа, перетаскивание с отменой Escape,
  точные X/Y, масштаб и порядок спрайтов, быстрые позиции и возврат к автоматическому
  размещению. Команды сохраняются до следующего изменения и работают для любого
  персонажа, независимо от говорящего; undo/redo, копирование реплики и сохранение
  поддержаны. Редактор и MonoGame используют общий расчёт размещения.
- Имя говорящего показано над текстом. Цвет фрагмента задаётся `§#RRGGBB`,
  `§r` возвращает цвет CSS, `§§` выводит символ `§`. Цвета работают в редакторе
  и игровом окне через общий парсер; палитра `§0–§f` не поддерживается.
- «Запустить сцену» / F6 открывает настоящее окно MonoGame. Линейная сцена без
  блоков начинается с выбранной реплики и допускает навигацию «Назад / Вперёд»
  с восстановлением команд персонажей. Сцена с блоками/потоком начинается с начала,
  «Назад» выключено. → / Enter / Space продолжают только ожидание ввода;
  Escape закрывает верхнее меню; когда меню нет — предпросмотр.
  Используется снимок несохранённого проекта: исходный файл не меняется.
  Повторный F6 заменяет окно новым снимком. Изменения не подгружаются автоматически.
  При закрытии редактора завершается только его собственный процесс предпросмотра.

Порядок настройки персонажей и запуска описан в [справке по сцене](docs/scene-preview.md).

Горячие клавиши: Ctrl+N — создать, Ctrl+O — открыть, Ctrl+S — сохранить,
Ctrl+Shift+S — сохранить как, Ctrl+W — закрыть проект, Ctrl+Z — отменить,
Ctrl+Y — повторить, F5 — обновить ресурсы и Git, F6 — запустить текущую сцену.
В обозревателе доступны файл проекта, сцены, изображения, персонажи и изменения Git.
ID выбранных сцены и реплики, а также ключ локализации
показаны в правой панели. Автосохранение и восстановление после сбоя ещё не реализованы.

## Проверка

```powershell
./scripts/check.ps1 -CaptureScreenshots
```

Для проверки настоящего игрового окна на машине с рабочим графическим окружением:

```powershell
./scripts/check.ps1 -CaptureScreenshots -NativeRuntime
```

Для подготовки и проверки автономного Windows-экспорта добавьте `-WindowsExport`.
Для установщика, включая установку/удаление тестовой игры, используйте `-WindowsInstaller`.

Скрипт восстанавливает закреплённые зависимости, собирает всё решение в Release
и запускает поведенческие тесты с TRX-отчётами в `TestResults/`.
Снимки фактически отрисованного окна сохраняются в `artifacts/screenshots/`.
Без PowerShell можно выполнить:

```sh
dotnet restore NovellMaker.slnx --locked-mode
dotnet build NovellMaker.slnx -c Release --no-restore
dotnet test NovellMaker.slnx -c Release --no-build
```

Тесты проверяют JSON и реальную файловую систему, стабильность ID, независимость
проектов, отменённые/неуспешные операции, сохранность черновика, внешние изменения,
повторное открытие того же файла, защиту от повторного запуска команд и снимок
сохранения при параллельном изменении данных. Git-тесты создают настоящие временные
репозитории и конфликты; отдельно проверяют запрет запуска внешнего fsmonitor hook.
Дополнительно проверяются миграции v1/v2/v3/v4/v5/v6/v7/v8/v9 → v10 без неявной записи, строгая валидация
вложенных данных, многоязычные реплики, сохранность ID при перестановке, undo/redo,
закрытые вкладки, CSS-ошибки и интерполяция ключевых кадров. Headless-тесты используют
настоящее окно, XAML, Skia, ввод мышью/клавиатурой, Ctrl+S и Ctrl+Z/Ctrl+Y; проверяют
одиночный шаг между репликами, CSS-цвет с прозрачностью, анимацию и видимость элементов.
Изображения проверяются настоящими PNG/JPEG: копирование и декодирование, ограничения
размеров, повреждённые файлы, перенос каталога, конфликты Save As, сохранность ID
и undo/redo. GUI-тест импортирует файл кнопкой, проверяет миниатюру, предпросмотр,
переименование, поиск и привязку задника с отменой/повтором через клавиатуру.
Отдельный тест управляет задержкой сервиса и проверяет запоздалый результат
при смене изображения и отключении/повторном подключении предпросмотра.
Тесты исполнителя проверяют восстановление состояний, скрытие, несколько персонажей,
запуск с выбранной реплики, отсутствие перевода и повреждённые ссылки. GUI-тест
создаёт персонажа и состояния, назначает изображения и говорящего, проверяет имя,
цвет и задник в общей сцене. Нативные проверки запускают отдельный MonoGame-процесс,
проверяют реальные пиксели кадра, переходы, перезапуск и очистку временных снимков.
Размещение дополнительно проверяется командами для не говорящего персонажа,
наследованием, сбросом, восстановлением назад, строгим чтением v6 и миграцией v4.
GUI-тест меняет параметры, перетаскивает реальный спрайт, отменяет жест через Escape
и проверяет undo/redo. Нативный кадр проверяет положение, масштаб и перекрытие слоёв.
Без `-NativeRuntime` тесты графических процессов явно пропускаются.

Локальная проверка выполнена на Windows. CI-процесс подготовлен для Windows,
Linux и macOS в `.github/workflows/ci.yml`, но удалённые прогоны здесь не выполнялись.
Нативный MonoGame-предпросмотр проверен на Windows. Нативные системные диалоги
и игровой запуск на Linux/macOS требуют отдельной проверки.
Проверка внешних изменений перед сохранением не является межпроцессной блокировкой:
запись другим приложением между проверкой и заменой файла пока возможна.
Поддерживаются миграции v1/v2/v3/v4/v5/v6/v7/v8/v9 → v10 и сохранение в v10. Предыдущие редакторы не откроют
сохранённый v10; для сохранения старого формата используйте отдельную копию проекта.
Статическое состояние в редакторе и игра используют один `ScenePlayer`.
CSS-анимация плашки вычисляется Core и отображается в обоих интерфейсах.
«Назад» в F6 линейной сцены без блоков восстанавливает её команды;
в самостоятельной игре навигация назад недоступна. Произвольный rollback Lua
и ветвлений отсутствует. Без ручных команд персонажи располагаются
автоматически внизу сцены. Ручное размещение, масштаб и порядок спрайтов работают;
вращение, анимации частей и отдельные слои задника ещё не реализованы.
Сейчас используются системные шрифты; упаковка шрифтов в экспортированную игру
относится к следующим этапам. Первая загрузка крупного изображения между репликами
может кратковременно задержать игровой кадр.

## Устройство

`NovellMaker.Core` содержит модели проекта/сцен/реплик/изображений/персонажей,
JSON-хранилище, общий исполнитель сцены, парсер цветных фрагментов, CSS-парсер
и вычисление анимации без Avalonia и MonoGame. `NovellMaker.Editor` содержит окно, редакторскую
сессию с историей, вкладки, библиотеку изображений, образец оформления, диалоги и Git-сервис.
Проверка и декодирование изображений выполняются через SkiaSharp 3.119.4,
версия совпадает с используемой Avalonia зависимостью. Одновременно декодируются
не более двух файлов; загрузка предпросмотра выполняется вне UI-потока.
Кнопки и горячие клавиши вызывают одни и те же команды сессии. Git запускается
асинхронно, без shell, с тайм-аутом и отключённым `core.fsmonitor`.
`NovellMaker.Runtime` — отдельный запускаемый игровой модуль на
[MonoGame DesktopGL 3.8.5.1](https://www.nuget.org/packages/MonoGame.Framework.DesktopGL/3.8.5.1).
Он читает снимок проекта и использует тот же исполнитель без зависимости от редактора.
Сборка редактора копирует его в подкаталог `Runtime/`; для запуска готового предпросмотра
не требуется вызов `dotnet build`. Минимальный экспорт использует отдельный готовый
шаблон self-contained Windows x64; установщик EXE упаковывается локальным NSIS 3.13.

Основной исполнитель — `ScenarioPlayer` с сериализуемым `GameState` и внешним
шагом времени. `ScenePlayer` предоставляет кадр сцены и совместимую навигацию
для прежних сцен. MoonSharp 2.0.0 формирует ограниченные очереди общих действий.
Следующие расширения — полноценные инструменты мини-игр, расширения звука и обновления установленной игры.
